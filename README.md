# Finance Architecture Studio · synthetic POC

An external finance agent calls approved SAP finance capabilities, checks the returned evidence and produces a month-end reconciliation. This is the **architecture story** shown by the demo. The runnable implementation is a Node-built, Fiori-inspired interface over a Python and SQLite simulator. Its four tabs are **Business workspace**, **Live architecture**, **Evidence & correlation**, and **Architecture questions**. Vendor names describe simulated boundaries. No SAP, AWS, Google, Databricks, BDC, Portkey or model account is connected.

The demo opens on a simulated Fiori-style **My Home** page. Select the **Finance Reconciliation Agent** tile to enter the four-workspace application, or select one of six **Open decisions** to go directly to its architecture flow, owner, next action and proof gates. The Home control returns to My Home. There is no real sign-in session. The shell, app tile and worklist are custom React/CSS, not SAPUI5 or an official SAP application. A footer on both levels states that the app is for demo and learning purposes only.

Inside the application, the Business workspace follows a list-report pattern: a page header, finance KPIs, period and status filters, a full-width close worklist, and selected-period details. **Ask Finance Agent** opens a side panel instead of occupying the page by default. A nonzero variance is marked for review even when source snapshots are comparable. On shorter screens, the worklist scrolls within its own panel so the close summary stays visible.

The application shell has a working **Menu** for My Home, close worklist, live architecture, evidence, architecture questions and the agent panel. Agent replies offer contextual actions to open the reconciliation report, inspect source evidence and follow the component trace. The actions retain the synthetic case identifier so an older answer can reopen its own case.

The original v2 POC prompt established the synthetic architecture and finance controls. Later user requests superseded its two-tab layout with four tabs and added the decision lab, document investigation, compact landscape architecture, and Business report dialog. The original no-live-integration and no-real-posting boundaries still apply. Clear chat removes conversation messages only; it keeps the selected case and evidence. At 1440 × 900, the four tabs have equal width and the Business workspace uses internal pane scrolling. A compact landscape layout keeps all 12 architecture zones visible at 1536 × 720 CSS pixels, including a browser zoomed to 125% on a 1920 × 900 display.

## Run locally

`release/finance_reconciliation_local_windows.zip` is a clean Windows laptop bundle. Extract it to a writable folder and double-click `Start Finance Demo.cmd`. The first launch creates a local Python environment and installs the small `requirements-local.txt` web runtime; later launches reuse it. The browser opens the FastAPI version at `http://127.0.0.1:8876/`. The included `frontend/dist` assets work without Node or Git at runtime. See [local laptop guide](docs/LOCAL_LAPTOP_GUIDE.md) for prerequisites, port changes and the offline/package-index constraint. To rebuild the frontend after source edits, run `npm ci` and `npm run build` in `frontend`.

For a controlled presentation setup, the ZIP also includes four numbered Windows scripts: `01_Check_Prerequisites.cmd`, `02_Install_Local_Runtime.cmd`, `03_Run_Local_Demo.cmd` and `04_Verify_Local_Demo.cmd`. Run verification in a second window while the server stays open.

The hosted Streamlit My Home page also offers **Download Windows bundle**. Streamlit serves the versioned ZIP committed with the app; the displayed size and SHA-256 prefix help identify the download. This link appears only when the hosted bundle exists.

`py -3 local_demo.py --mode streamlit` or `run_streamlit.ps1` starts the **local** Streamlit version at `http://127.0.0.1:8502/`. It uses the same Node-built UI as a Streamlit custom component and an isolated in-memory SQLite fixture per viewer session. The compiled `frontend/dist_streamlit` assets are included so Streamlit Community Cloud will not need a Node build step. `requirements.txt` contains the Python dependencies for that entrypoint.

The existing public Streamlit deployment uses `streamlit_app.py` from GitHub. Local changes are not visible there until the repository is updated and Community Cloud rebuilds the app.

## Architecture team demo

1. From the simulated Finance Launchpad, open the **Finance Reconciliation Agent** tile, then select **Live architecture**. Select a synthetic month, S1 Apigee or S2 AgentCore route, and a pace. Start the run. The external-agent view is a simulation driven by the local Python runtime.
2. Watch the five-stage journey advance from finance intent to external-agent invocation, SAP tool call, SAP evidence and deterministic reconciliation. Each state is derived from a persisted request or response event. The topology separates the external agent domain, SAP-owned finance path, enterprise data evidence and return. Select a zone, then open **Component trace** in Evidence for its purpose, owner, contract, bounded payload and live validation limit.
3. Load a stored case, replay, pause, or return to live state. The diagram uses a company-neutral projection: business identifiers and scope fields are removed before events reach this view.
4. In **Business workspace**, ask `Reconcile February 2026`, `Why is there a variance?`, `Show source evidence`, `How does approval work?`, `Compare S1 and S2`, or a vendor/component question. The answer is deterministic or evidence-bounded. An unknown question gets an explicit limit rather than a fabricated result. Every follow-up records a component trace.
5. Use the month-end work center to review all 12 periods, three stale-source exceptions and the selected case. **Finance sources** in Evidence contains account balances, illustrative journal records, source snapshots and calculation inputs. November 2026 has a comparable $25,000 synthetic variance. February has a $0 match. For a comparable nonzero case, propose a signed variance marker; switch the demo role to finance approver to create a local `SYN-` marker receipt. This role switch is a simulation, not a security boundary.
6. For the agentic scenario, reconcile November 2026 and open the **Evidence & correlation** link. Select **Investigate variance**. The proof dossier updates through readiness, a gateway-routed four-document comparison, hypothesis testing and an action recommendation. The missing-document profile ties $1,000,000 in S/4HANA to $975,000 in Central Finance and identifies one $25,000 document. Select **Apply simulated reprocess and re-reconcile** to see the source and downstream evidence refresh and a new $0 reconciliation. Choose **Mapping conflict** on a fresh case to see the agent hold the action for review. The architecture tab shows the same persisted component events without company-specific scope.
7. Open **Architecture questions** and click one of six open alignment questions. The Python evaluator shows up to 12 visual handoffs; **Question handoffs** in Evidence contains each component's received input, control owner, redacted identity reference, output, synthetic evidence ID and remaining live proof. Compare S1 Apigee, S2 AgentCore and **S3 combined candidate**; S3 is not approved. Run denied probes for a missing target, missing SAP principal, unapproved write, unregistered tool or unapproved partner. Download the synthetic decision packet from Evidence for meeting notes; it never records a human architecture approval.

8. On a selected architecture question, open **Hosting & dependencies**. The implementation plan covers S1, S2 and S3 separately. Select a handoff to see its configuration work, prerequisites, accountable team and nonproduction acceptance proof. The side panel lists route-level open decisions and dependencies specific to the chosen question. The links lead to public AWS, Google and SAP product documentation; no tenant configuration or approval is implied.

The **Implementation** section in Evidence identifies the React/Node presentation, Python execution and SQLite event store. They power the simulator and are not separate agents. The S3 combined path remains a decision probe in Architecture questions; the live finance run offers only the S1 and S2 simulated alternatives.

The fifth **MCP approaches** tab compares S1 direct Apigee, S2 AgentCore-hosted SAP finance MCP adapter, and S3 AgentCore Gateway in front of SAP Apigee MCP. Select an approach and handoff to see AgentCore and SAP responsibilities, configuration, dependencies, acceptance proof, benefits, tradeoffs and open decisions. The SAP Apigee domain direction is a discussion baseline; S3 federation, direct agent access, identity propagation and tenant onboarding are not approved or proven. The tab links to the question probes. At desktop width the five tabs fit in one row; detailed records scroll inside their panes. On narrow screens the layout scrolls naturally to preserve legibility.

## Data and verification

SQLite contains December 2025 through November 2026: 12 months, six synthetic G/L accounts, four source systems, 288 per-account balances and 144 journal evidence rows. The bounded seed uses one synthetic finance scope; it is not a document ingestion or arbitrary-company reconciliation service. The closing-balance rule is S/4HANA minus comparable Central Finance. BW/4HANA and Databricks provide freshness and context; an advisory model explanation never determines the amount.

The November investigation adds four synthetic replication comparison documents whose totals tie to the aggregate snapshots. The `sap.compare` operation follows the selected gateway, domain tool, SAP API Management, custom iFlow and Central Finance role path in the simulator. Each plan step persists evidence IDs, a SHA-256 digest and a decision. Once document investigation starts, the old case cannot create a variance marker. A simulated reprocess is an explicit local operator action; it is not SAP AIF execution or a balanced FI posting.

Run the Python suite with `python -m pytest -q tests/test_poc.py --basetemp=.pytest_tmp`. Run `python scripts/qa_v3.py`, `python scripts/qa_release.py` and `python scripts/qa_agentic.py` and `python scripts/qa_decision_lab.py` with their local servers active for Chromium UI checks. `python scripts/package_streamlit.py` creates the allowlisted upload archive at `release/finance_architecture_streamlit.zip`. It contains the compiled Node-built interface, Python entrypoint, source modules, minimal pinned dependencies and an integrity manifest; it excludes local databases, environment files, screenshots and Node dependencies. The repository also includes the compiled Streamlit assets; select `streamlit_app.py` as the entrypoint for a separate deployment. See [architecture mapping](docs/ARCHITECTURE_MAPPING.md), [evidence](docs/DEMO_EVIDENCE.md) and [limitations](docs/POC_LIMITATIONS.md).
